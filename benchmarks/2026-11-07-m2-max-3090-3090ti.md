# RTX 3090 and RTX 3090 Ti on a 16-inch M2 Max MacBook Pro (2026-11-07)

Reported by **openresearchtools**, copied here with their consent and credit.
Original inference measurements: 2026-11-07 UTC. The runs were automated
(attribution in the source comment: GPT 6.1 SOL Ultra); the account operator
handled the hardware. Contact: [openresearchtools](https://github.com/openresearchtools).
This is a third-party report; nobody in this repository has rerun it.

Source: [issue #17 comment](https://github.com/joshuaswarren/omarchy-egpu/issues/17#issuecomment-6708472440)
and the [full record in their fork](https://github.com/openresearchtools/omarchy-egpu/blob/main/benchmarks/2026-11-07-m2-max-3090-3090ti.md).
Raw evidence archive (retained JSON and stderr, excluded failed attempts,
kernel config, driver patches, SHA256SUMS):
[issue17-evidence.tar.gz](https://github.com/openresearchtools/omarchy-egpu/releases/download/v0.1.0/issue17-evidence.tar.gz),
archive SHA256 `e4a0b611ec793503fa606b11149380160efce982d1e322431909bababdd59e97`.

Verification performed on receipt by this repository: the downloaded archive's
SHA256 matches the value above, all 593 archived files match the archive's own
SHA256SUMS manifest, and two table cells spot-checked against the retained
llama-bench JSON match exactly (RTX 3090 Ti Llama-2 CUDA FA-off pp512 3153.80
and RTX 3090 Qwen Vulkan FA-on tg128 39.35). Every table mean and standard

## Driver, kernel and host

- Host: 16-inch MacBook Pro M2 Max 2023, 96 GB RAM (`Mac14,6`), 16 KiB pages.
- Kernel: signed Omarchy `linux-aurora 7.2.11.aurora14-1`, running
  `7.2.11-14-1-ARCH`. Declared source: omacom/linux-aurora. **The exact kernel
  source-commit ancestry is unverified; no local device-tree fix is attributed
  to these runs.** The record includes the full running config, package
  provenance and a read-only DT-property extract (packaged DTB hash matches
  its package mtree; tunnel-parent ranges empty; matching 64-bit prefetch
  windows).
- Driver: NVIDIA open modules/userspace/GSP **615.78.08**, built from the
  signed Omarchy `nvidia-open-dkms 615.78.08-3` package (base SHA256
  `54fce3d5e529f561c13100396eee19145df5258b77193dcdb92572dddb20a11d`).
  Five patches, all with hashes in the archive: the three upstream fixes
  #1480 (16K page size), #1481 (2 MiB DMA submap alignment) and #1482 (Apple
  tunnel root port entry), plus two local carries, `0004-arm64-kernel-bti`
  (target-kernel-conditional BTI build flags) and
  `0005-msi-probe-without-legacy-irq` (deferred early legacy-IRQ rejection for
  MSI-capable cards). **The two local carries are not upstream merges.**
  `NVreg_RegistryDwords="RmForceDisableIomapWC=1"` was applied.
- CUDA 13.4 (`nvcc 13.4.92`); llama.cpp `65840ed53c8653bfbf3e9014d9cbf71ac8c08725`,
  the same commit as our three-card record.
- Enclosures: original Razer Core X (both cards), authorized Thunderbolt 3 at
  40 Gb/s; endpoint links reached PCIe 8.0 GT/s x4 during measurement. These
  are tunnel/PCI readings, not measured payload bandwidth.
- PSU model, connector arrangement and wall power: not recorded (the method
  allows this; it is stated, not inferred).

## Conditions

Stock clocks and default limits (3090 Ti 450 W; 3090 350 W), four CPU threads,
batch 2048/microbatch 512, f16 K/V, split mode `none`, explicit selected card,
three warm-up repetitions, at least 60 seconds idle, then five timed
repetitions. The Apple GPU ran the desktop. An active-desktop idle-gate
exception allowed Hyprland KMS and Chromium DRM-only handles only when the
holder had no `/dev/nvidia*` descriptors and the selected GPU's NVML process
list was empty; the purpose of Chromium's DRM handle was not established.
Host load was below 1.0 before each reference phase. Some cases had both cards
attached; each timed run selected exactly one card, and the one timing attempt
invalidated by a second enclosure attaching mid-run is excluded.

Vulkan qualification: the completed FA-off rows use the **KHR fallback**
(`GGML_VK_DISABLE_COOPMAT2=1`, `GGML_VK_DISABLE_COOPMAT2_DECODE_VECTOR=1`;
device log confirms `KHR_coopmat`). FA-on rows report the default
`NV_coopmat2v`. **Default FA-off Vulkan attempts aborted or segfaulted and are
excluded**; their failures (exit 134 warm-up, 139 timed) are preserved with
backtraces in the archive's `excluded/` tree and are separate from the
completed fallback measurements. The Ti KHR-fallback pp2048 companion has high
variance (1717.07 +/- 1188.77); all five samples are retained and it must not
be read as a stable typical rate or a feature-matched comparison.

Model files and SHA-256 are pinned in the source comment; the Qwen3.8-27B
Q4_0 hash matches our B60 record and the Llama-2 hash matches the `78b8f977`
prefix in our README.

## Two-card CUDA supplement: Qwen3.8-27B Q8_0 with embedded MTP

The same two eGPUs ran a document-analysis task (War and Peace excerpts,
native chat template, reasoning disabled) with 66/66 layers offloaded across
both cards, `--split-mode layer --tensor-split 1,1`, one slot, context 262,144,
q8_0 K/V for target and draft caches, embedded `draft-mtp` with draft maximum 3.
Every measured request cleared the slot, reported zero cached prompt tokens and
generated exactly 2,048 output tokens. n=3 rows show mean +/- sample SD; n=1
rows have no SD. Acceptance is pooled accepted/drafted tokens.

This is an ARM two-card supplement, not the requested x86 scaling series and
not a controlled one-versus-two-card comparison. The fixed output budget can
end the analysis early; this measures generation and MTP behavior, not answer
accuracy. Familiarity with the public novel may affect MTP acceptance. Peak
board readings reported in the source comment (1 Hz samples, not wall power;
not retained in the evidence archive, so not independently checked here):
Ti 20,001 MiB used VRAM / 338.0 W / 71 C; 3090 23,564 MiB / 307.6 W / 69 C.
Same-boot recovery after surprise unplug is unmeasured here; a later
surprise-unplug test is reported separately in issue #19.

## What this record does not show

- No rerun by this repository; all numbers are the reporter's.
- Kernel source-commit ancestry unverified; no local device-tree fix attributed.
- The two local driver carries are not upstream and not reviewed here.
- The default Vulkan FA-off path fails on this stack; only the KHR fallback
  completed.
- No macOS Metal baseline, no x86 comparison, no measured payload bandwidth,
  no PSU or wall-power measurement, no same-boot surprise-unplug recovery.
