# Dual-card eGPU record: Arc Pro B60 + RTX 5060 Ti on one tunnel (2026-10-24)

Same boot, same host: 16-inch M1 Max laptop, eGPU kernel build
`7.1.12-2-20261013.20-egpu-ARCH`, one-shot boot entry. Both cards sit behind a
single Thunderbolt/USB4 tunnel: the Arc Pro B60 in a Sonnet Breakaway
enclosure, the RTX 5060 Ti dock connected to the Sonnet's downstream
Thunderbolt port. Enumeration after authorization: B60 at `0001:05:00.0`,
5060 Ti at `0001:09:00.0`.

Boot command line additions the dual-card topology needed (beyond the
single-card setup): `pci=noiovbars,realloc=on,hpbussize=8,hpmemsize=64M,hpiosize=4K,hpmmioprefsize=256M`.
Without `hpmmioprefsize`, the kernel sizes the tunnel's prefetchable hotplug
window for one card; two 256 MiB-aligned branch windows (280 MiB for the B60,
288 MiB for the 5060 Ti) do not fit, and the NVIDIA BAR assignment fails with
"no space" on alignment. With the 256 MiB prefetchable reservation both
cards' BARs assign. Thunderbolt authorization can also land a few seconds
after the network stack; the checks below waited for both enclosures to
report `authorized` before proceeding.

`using device Vulkan0 (NVIDIA GeForce RTX 5060 Ti) (0001:09:00.0)`; the
dual row logs both (`Vulkan0` the B60, `Vulkan1` the 5060 Ti) with both ICDs
loaded. The CUDA row logs `Device 0: NVIDIA GeForce RTX 5060 Ti`.

Health in the same boot: zero Xid lines in the kernel log, zero xe/ANV
error lines in the bench logs, both BARs assigned (the 5060 Ti's 64-bit
prefetchable window at a 256 MiB-aligned address).

Two larger models ran in a second same-boot session on the same topology: Qwen3.8-27B Q8_0 (27.04 GiB; 66/66 layers split, weights 15050 MiB on the B60 + 10922 MiB on the 5060 Ti) and Llama-3.3-70B-Instruct IQ3_M (29.74 GiB; 81/81 layers split, weights 17276 MiB + 12743 MiB). Neither fits a single card in this setup (24 GB and 16 GB); both ran fully on GPU split across the two. Zero Xid lines, zero xe/ANV error lines in that boot as well.

A Vulkan queue A/B on the B60 was attempted in the same window; its
answer-comparison gate reported INVALID (no completion line in the captured
CLI outputs), so no queue conclusion is published from it. The bench-side
rows exist in the run receipt only.

## Honesty box

- n=3 repetitions, one boot, one machine, one cable topology. No
  cross-machine or cross-topology ratio is claimed.
- The B60 numbers require the local kernel and ANV work described in the
  [B60 record](2026-10-23-b60-m1max-llamacpp-vulkan.md); the 5060 Ti numbers
  require the NVIDIA route and patches described in the
  [5060 Ti record](2026-10-23-5060ti-m1max-nvidia.md). Nothing here is a
  stock-system recipe.
- The dual-card rows are the first same-boot measurements of both cards
  behind one tunnel on this host; the split loading is what llama.cpp chose
  with both Vulkan devices visible.
- The 27B Q4_0 model also fits the B60 alone (24 GB VRAM); the dual row
  shows the split works, not that it is needed. A single-card B60 27B
  comparison is not yet measured.
